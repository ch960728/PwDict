# 암호화 알고리즘 정리

## 대칭 암호화 vs 비대칭 암호화

| 구분 | 대칭 | 비대칭 |
|---|---|---|
| 키 | 암호화/복호화에 같은 키 사용 | 공개키(암호화) + 개인키(복호화) |
| 속도 | 빠름 | 느림 |
| 용도 | 대용량 데이터 암호화 | 키 교환, 인증서, HTTPS 핸드셰이크 |
| 예시 | AES, ChaCha20 | RSA, ECC |

> PwDict는 로컬 파일 암호화 → 대칭 암호화(AES) 사용

---

## AES (Advanced Encryption Standard)

현재 전 세계 표준 대칭 암호화 알고리즘. 미국 NIST가 2001년 표준으로 채택.

### 키 길이별 종류

| 종류 | 키 길이 | 보안 수준 |
|---|---|---|
| AES-128 | 128비트 (16바이트) | 충분히 안전 |
| AES-192 | 192비트 (24바이트) | 높음 |
| AES-256 | 256비트 (32바이트) | 매우 높음, 군사/금융 수준 |

> PwDict는 AES-256 사용 — 32바이트 키가 필요한 이유

### 운용 모드 (Mode of Operation)

AES 자체는 16바이트 블록 하나만 암호화한다. 긴 데이터를 암호화하려면 블록을 어떻게 이어붙일지 결정하는 **운용 모드**가 필요하다.

| 모드 | 특징 | 무결성 검증 | 비고 |
|---|---|---|---|
| ECB | 블록을 독립적으로 암호화 | 없음 | 패턴 노출 위험, 사용 금지 |
| CBC | 이전 블록 결과를 다음 블록에 XOR | 없음 | IV 필요, 패딩 오라클 취약점 |
| CTR | 카운터를 암호화해 키스트림 생성 | 없음 | 스트림 암호처럼 동작 |
| **GCM** | CTR + 인증 태그 | **있음** | 현재 표준, PwDict 사용 |

## AES-256-GCM (PwDict 사용)

GCM = **Galois/Counter Mode**

암호화와 무결성 검증을 동시에 처리하는 **인증 암호화(AEAD)** 방식.

```
평문 → [AES-256-GCM] → 암호문 + 인증 태그(16바이트)
                ↑
              Nonce (12바이트, 매번 랜덤)
```

### 구성 요소

| 요소 | 크기 | 역할 |
|---|---|---|
| Key | 32바이트 | 암호화 키 (PBKDF2로 도출) |
| Nonce | 12바이트 | 같은 키로 암호화해도 매번 다른 결과 보장 |
| Ciphertext | 가변 | 암호화된 데이터 |
| Tag | 16바이트 | 무결성 검증용. 키가 틀리거나 데이터가 변조되면 복호화 실패 |

### 왜 GCM인가?

- **무결성 검증**: 잘못된 패스워드로 복호화 시도 시 `InvalidTag` 예외 발생 → 패스워드 오류 감지에 활용
- **변조 감지**: vault.dat 파일이 외부에서 수정되면 복호화 실패
- **빠름**: 병렬 처리 가능

## PBKDF2 (Password-Based Key Derivation Function 2)

패스워드 → 암호화 키 변환 함수.

### 왜 패스워드를 그냥 키로 못 쓰나?

- AES-256은 정확히 32바이트 키 필요
- 사람 패스워드는 길이가 제각각
- 짧은 패스워드는 엔트로피(무작위성)가 낮아 브루트포스에 취약

### PBKDF2 동작 방식

```
패스워드 + Salt → [SHA-256 해싱 × 100,000번] → 32바이트 키
```

| 요소 | 역할 |
|---|---|
| Salt | 랜덤 16바이트. 같은 패스워드라도 다른 키 생성 → 레인보우 테이블 방어 |
| 반복 횟수 | 100,000번 → 브루트포스 시 패스워드 1개 검증에 오래 걸림 |
| SHA-256 | 해싱 알고리즘. 단방향이라 키에서 패스워드 역산 불가 |

### 레인보우 테이블이란?

흔한 패스워드 → 해시값을 미리 계산해둔 테이블. Salt가 없으면 테이블 조회만으로 패스워드를 역산할 수 있다. Salt를 섞으면 미리 계산한 테이블이 무의미해진다.

## 유사 알고리즘 비교

### 키 도출 함수 비교

| 알고리즘 | 특징 | 보안 수준 |
|---|---|---|
| PBKDF2 | 표준, 널리 사용. CPU만 사용 | 보통 |
| bcrypt | 메모리 사용량 고정. GPU 브루트포스 방어 | 높음 |
| **Argon2** | 메모리 + CPU 모두 사용. 현재 최강 표준 | 매우 높음 |

> Argon2가 더 강하지만 PBKDF2도 반복 횟수를 높이면 실용적으로 충분히 안전하다.

### 대칭 암호화 알고리즘 비교

| 알고리즘 | 특징 | 용도 |
|---|---|---|
| **AES-256-GCM** | 하드웨어 가속, 표준 | 파일 암호화, TLS |
| ChaCha20-Poly1305 | 소프트웨어 구현 빠름, 모바일에 유리 | TLS, WireGuard |
| 3DES | 구식, 느림 | 레거시 시스템 |

## PwDict에서의 흐름 정리

```
마스터 패스워드 (문자열)
        ↓
  PBKDF2 + Salt (16B)
        ↓
   32바이트 AES 키
        ↓
  AES-256-GCM + Nonce (12B)
        ↓
  암호문 + Tag (16B)
        ↓
vault.dat: [Salt 16B][Nonce 12B][암호문 + Tag]
```
